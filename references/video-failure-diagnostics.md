# 真实视频反馈：证据、定位与局部修订

提示词定位可用分镜／镜内阶段编号，实际视频证据记录观察秒数。尾段过载按[镜头执行契约](shot-execution-contract.md)返修串行事件与并发反馈，再核终态观察机会。

用户提供实际视频、抽帧、音轨或具体文字反馈后按需使用；没有成片时不虚构观察。以用户目标、真实提交的提示词和可取得的生成条件为准，先理解作品意图，再找最小失败点。用户只要局部返修时保持范围，修订流程不要求自动生成、付费调用或修改技能本身。

## 区分可用证据

- **实际观看的视频**可支持对已观看片段的动作、时序、遮挡、位置与镜头衔接判断；仅收到文件名或存在文件不等于已观看。
- **抽帧、截图或接触表**可支持所见静态画面和有限时点比较；帧间行为、原速节奏与连续接触可能未知，不能仅凭稀疏抽帧证明或否定运动流畅。
- **实际听到的音轨**可支持音色、声音事件及其自身时序；音画同步需同时取得可对应的画面和声音，并有足够时间精度，单独音频不能证明同步。静音视频不能证明原始作品一定无声。
- **用户文字描述**是用户报告，可作为定位线索；不假称自己看到未提供的画面、听到未取得的声音。原稿、素材、绑定、模型版本、参数、时间点缺失时写明未知。

同一个结论区分：**直接观察／用户报告 → 可检验的原因假设 → 尚不确定之处**。提示词含糊、状态冲突或容量过载可确认为文本设计问题；文本已描述而视频未体现，只能确认本次未遵循，原因可能涉及模型、参考素材、设置或随机性，缺证据时不将其归咎于模型。多次同条件检验可增强判断，但不能凭单次输出断言根因。

## 统一故障记录格式

每条问题按下表逐条记录；没有取得的字段写「未知」，不省略、不合并成一句笼统结论：

| 字段 | 填什么 |
| --- | --- |
| 时间位置 | 第几秒到第几秒，或第几镜 |
| 预期 | 提示词／用户要求本来要发生什么 |
| 实际 | 视频里能直接观察到什么 |
| 差异 | 哪一项要求没有实现 |
| 证据等级 | 原片、抽帧、音轨、用户报告（可多选） |
| 可能来源 | 文本设计、模型执行、素材／参数、未确定 |
| 最小修复 | 优先改哪一句、哪段动作或哪项镜头规则 |
| 复测结果 | 已改善／未改善／尚未复测 |

「已改提示词」不等于「问题已解决」：没有重生成并观看，复测结果只能写「尚未复测」，也不把单次重测写成稳定结论。修复接点的选择与最小修订复用[反馈修订](feedback-repair.md)，不另建第二套故障修复体系。

## 按现象排查

| 反馈现象 | 根据任务优先核对 |
| --- | --- |
| 两人对打像各自挥舞 | 双方意图与位置、攻击端及接触观察、真实距离、反应；原作允许的画外与故意隔空除外 |
| 特效遮掉关键变化 | 主要接触／目标、遮挡持续与观看角度、前后变化，保留用户要求的强度和留白 |
| 要求连续交锋却轮流待机 | 双方运动与威胁、施法时路线、事件容量；有意等待、诱敌和剧情停顿不当成故障 |
| 指定媒介退成通用光效 | 已提交提示词中的材质、形态、变化与实际观察；区分可见现象和原因假设，允许用户要求的混合风格 |
| 武器、人物或场景复原 | 原素材职责、持有者、损坏与时空设定、跨段继承；幻术、恢复、跳时或故意不连续按设定 |
| 换位或越轴后迷向 | 角色／地标／朝向、原镜头与新镜头之间的观察证据；实验、梦境和有意断裂不自动判错 |
| 高潮或收束没有兑现 | 查指定事件是否出现、决定性变化是否可辨、尾态与持续时间；不默认加入攻击、爆炸、摆拍或停顿 |
| 声音不符合要求 | 实际音轨、触发、静音／音乐与用户要求；有同步画面和音频才能检查对位 |

### 多项结尾结果未兑现时

先对照实际提交稿逐项列出预期终态，分别记为符合、偏离、未知或不适用；“看见爆墨”不能代替消散、地形变化与角色尾态的证据。沿 **终态 ← 直接结果 ← 决定性行动 ← 必要条件** 找最早可证实断开的接点，再核冲击触发、恢复相位和状态来源。只观察到抽帧未出现时写“在已检查时点未观察到”，不据此断言全片没有发生。

区分“文本没有交代结果／内部冲突”和“文本已交代但本次视频未呈现”；后者根因仍可能未知。只修相关接点并复查上下段状态，未重生成观看仍记尚未复测，不把一次偏差升级成全局削弱特效或删战术的规则。

## 保留有效部分，修复后再验证

核对目标与可取得的实际提示词、素材角色和参数，记录具体片段与观察依据；把观察、报告和原因假设分开。找与用户目标最相关的最小接点，选择修动作依赖、镜头、材质或状态承接，保留已有效的内容及相邻状态；不靠叠加抽象禁令或默认全稿重写。

有重生成授权与条件时，在尽可能一致的条件下查看修订结果，记录模型版本、输入、参数与次数；无相关证据只报告文字已改、成片待复测。旧故障片可用于诊断，不能证明新版本改善；多次测试也只支持其实际范围，不伪造成功率或统计显著性。若重复出现且用户授权修改技能，再回查规则层，不能把一次故障自动写成全局禁令。
