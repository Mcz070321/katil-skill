# 跨类型路由回归：16 条固定用例

本页用于版本升级、规则改动或新模块加入后的路由回归。它不评价文笔好坏，只检查**任务契约是否读对、模块是否按需加载、每个决策域是否只有一个主导**。

## 1. 判定方法

1. 只读主 `SKILL.md` 与本页，不先读全部专题。
2. 对每条用例写出：主导意图、题材、媒介、形式、导演模式、应加载模块、应禁用模块、空间模式（S1／S2／S3）；任务涉及原创概念时，另标概念档位（作者型／约束型／极简型）。
3. 不写完整提示词；只做路由决定，避免文笔掩盖路由错误。
4. 通过标准：
   - 媒介、形式、题材没有混成同一个维度；
   - 动作模块只在动作题材或用户明确要求时加载；
   - 每个决策域只有一个主导，约束模块不越权；
   - 动画任务不被真人物理与真人镜头语法强行覆盖；
   - 空间模式与任务匹配，不把 S1 的“禁米数”套到 S2。

**第14项固定原文：**“门外传来两下敲击。阿岚握住铜钥匙，却没有开门。灯影从门缝里一闪而过，她低声说：‘等等。’”以这四句的事实、否定、原话与开放终点作为忠实性依据。

本次保留16项输入、概念档位与路由意图，仅将条件移到注意列；“应加载”及 JSON 的 `expected_load` 只列必需模块名，条件模块另见 `conditional_load` 的 `module`／`when`。历史执行记录保留当时的输入快照，不冒充本次重跑。第2项“二维动画”和第12项“三维／混合”是原表的示例选择，但输入本身未明确指定媒介；实际盲判若保留媒介未定，不应仅因此判失败，也不应把示例当成用户硬约束。第13–16项在 `tests/routing_cases.json` 的 `concept_mode` 字段标注概念档位（约束／约束／极简／作者），用于检查概念判断本身，其余各项未要求原创概念；路由验证只判断任务、模块与权限，不将完整镜头质量、视频执行或容量评分当成路由结果。第15项可用数据趋势、对比、结构或时间变化表达核心信息，不强制空间隐喻。第9项只要求看懂追逐路线、速度与情绪时，不强制加载动作编排；出现明确搏斗、兵器接触、格挡或复杂交锋才按动作题材加载，避免把「追逐」一律当成必须或禁止动作模块。

## 3. 常见路由错误

- 看到“雨夜、对峙、刀、枪”就加载动作，忽略用户要的是关系戏。
- 看到“动画”就只加载动画模块，漏掉恐怖、爱情或叙事主导。
- 看到“故事板”就当成一种题材，漏掉媒介与形式分开。
- 看到“广告”就只写产品，漏掉人物、声音与空间。
- 看到“实验”就放弃全部空间逻辑；实验可以打破轴线，但仍要有内部逻辑。
- 看到“动作”就把特效拉满、把镜头全变成慢镜与环绕。
- 看到“真实”就强制所有任务符合现实物理，忽略科幻、奇幻、动画自己的规则。
- 让两个模块同时主导同一决策域，最后互相抵消。

**检查：先问“这次到底在创作什么”，再问“该读哪些模块”；不是先问“这属于哪个模板”。**
