# 能力库 v1.8.0（KATIL 3.7.5 内置）：200种角色技能与配套特效

本库提供200条稳定编号的角色技能卡，按20类组织。技能包含写实身体与器械动作、潜行侦察、救援、运动、机械与能量科幻，以及奇幻元素、时空、召唤和媒介化实体。每条都有机制、动作、效果、限制／反制、镜头声音与持续状态，不只是一串招式名。

## 按需读取

- 先看[分类和编号索引](ability-library/index.md)，只读当前剧情需要的分类。完整数据按分类保存在20个JSON文件中，`catalog.json`维护版本、范围和枚举。
- 用户已给能力时，先锁定其规则，只取匹配的动作或效果参考。需要设计新能力、角色招式、协作或非战斗技能时，才从相关类别挑选。
- 这些条目是可迁移的起点，不是世界通用权限，也不是白名单。库内无合适能力时可按当前规则继续创作，不能声称新方案已有稳定ID。

可用只读工具 `scripts/ability_library.py` 按ID、类别、世界类型、用途或关键词检索。例如，在实际技能目录下运行：

```text
python scripts/ability_library.py --category C06 --world 现实 --limit 3
python scripts/ability_library.py --id A081 A132
python scripts/ability_library.py --world 科幻 --role 防御 --limit 3
python scripts/ability_library.py --query "水 反射" --limit 3
python scripts/ability_library.py --validate
```

在其他工作目录执行时使用脚本的真实完整路径；脚本自行从安装位置寻找数据，不依赖当前工作目录。关键词是文本筛选，多个词需同时匹配；无结果就换条件或创作新方案，不能编造检索成功。没有脚本运行条件时，可直接按索引读取相应JSON。

## 选择顺序

1. **锁世界与媒介。** `world=现实`只允许身体、实际器械和可见材料反馈；`科幻`依赖明确获准的虚构装置、能源与边界；`奇幻`依赖当前世界认可的能力规则。动画／水墨等画风是呈现媒介，不自动赋予角色新能力。
2. **锁角色任务。** 根据进攻、防御、机动、控制、感知、潜行、支援、救援或交互挑条目；非战斗目标不强加敌人、爆炸或伤亡。
3. **核对条件。** 比较载体、范围、资源、动作幅度、限制、可反制点和人物现有持物；不因库里有召唤、分身或瞬移就自动给角色装备。
4. **改成当前动作。** 用本场人物名、锚点、目标、距离关系和对方应答改写。通常只选能服务当前段落的少量机制，不把200条或整类都塞进一个提示词，也不固定每个角色必须几招。
5. **回写状态。** 受力、器械能量、伤势、遗留物和环境破坏进入下一镜与跨段转场。成稿需要新角色、独立召唤体、可辨新形态或新场景时，按交付语言补对应生图提示词（默认中英双语；用户明确单语时只给该语言），由用户自行生成；不自动调用图片工具，查到条目不等于已有素材。

## 角色技能与影像表现分开

卡片中的`mechanism`决定角色实际能做什么，`vfx`决定如何看见其作用，`camera_sound`只建议有效观看方式，不自动变成镜头配额。多机位、真正一镜和严格POV仍服从用户条件；主观镜头不因卡片建议肩外或高位就离开角色眼睛。

锁定机制不等于锁死视觉表现。在用户要求幅度内，可重设同机制的主形体、体积、材质层、光色、展开与受力结果，不照抄卡片的小规模示例，也不为每种新视觉编新能力ID；独立杀伤、属性、控制方式与作用范围的变化才核对是否越过授权。具体构想按[特效与受创](effects-and-damage.md)，不默认载入全库寻找更大的招名。

科幻和奇幻的发光体、透明膜、冻结、空间形变等都是设定条件，不作为现实技术或人体能力事实。写实条目用于电影动作叙事，不扩写成现实危险操作、诊疗或武器教学。

新能力确需配套效果细化时，按主入口条件读取[特效与受创](effects-and-damage.md)。纯材质滤镜、调色、慢放或切镜不是新角色技能，不计入200条。

## 卡片字段

`id`为A001—A200，`category`为C01—C20，名称与编号稳定；`world`和`roles`用于筛选。`mechanism`写载体与作用，`action`写身体／器械动作及应答，`vfx`写具体形态与接触反馈，`counter_limit`写代价与可破解点，`camera_sound`写观看任务与声源，`residue`记录持续状态。`signature`是内部机制辨识键，不是给用户的技能喊话或画面文字。

用户要求展示库时可给ID与名称；普通视频稿直接把所选机制融进动态分镜，不默认输出库字段、自检表或屏幕技能字幕。
