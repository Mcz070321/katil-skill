# 通用创作核心：多维任务契约与模块决策权

KATIL 是**通用 AI 影视创作与导演系统**，不是动作、高速战斗或某一种画风的专用模板。核心负责理解意图、建立多维任务契约、给模块分配决策权、裁决冲突与做通用验收；专业模块负责深度。

本页在每次任务开始时读。它不替代各专业专题；只决定“这次到底在创作什么、该读什么、谁说了算”。

## 1. 任务契约：九个维度，不是一个主类型

在写任何提示词前，用一句话确认这次在创作什么。信息不足时只问真正影响结果的缺项；用户已给的部分不重复追问。

| 维度 | 要确定的内容 | 缺失时 |
| --- | --- | --- |
| 主导意图 | 观众看完最应获得的一个体验：理解关系、感到压迫、相信动作、记住产品、进入世界、学会信息 | 从用户动词与交付物判断；仍含糊时问一次 |
| 题材／情绪 | 动作、恐怖、爱情、喜剧、科幻、奇幻、犯罪、悬疑等；**可多选** | 可保留多个，不强迫缩成一个 |
| 媒介 | 真人、二维动画、三维动画、定格、混合媒介、未指定 | 未指定用中性电影语言，不默认真人电影；只有媒介会改变语法时才问 |
| 形式 | 单条短片、广告、故事板、长视频、系列、预告、预演 | 从交付物判断；未给总长不估总长 |
| 导演模式 | 写实、诗意、实验、商业、类型化、纪录片 | 从题材、参考与用途推断；模式不是滤镜 |
| 时长与平台 | 用户总长、分段时长、已确认平台限制与事件容量 | 默认按无时间码事件序，给总长则核容量；精确时间按下文 TIME 规则判断 |
| 观众与用途 | 影院、流媒体、短视频、广告投放、内部提案、教学 | 影响尺度、节奏、信息密度与结尾方式 |
| 硬约束 | 原著事实、品牌规范、台词、参考图职责、禁止内容、平台参数 | 单列，任何模块默认值不能覆盖 |
| 成功标准 | 看懂事件、感到压迫、记住产品、相信人物、看清动作、建立世界观 | 写进验收；不能只写“好看” |

任务契约是内部工作纸，不抄进复制块。用户改变意图时，先更新契约，再决定是否换模块。

**动画是媒介，故事板是形式，广告是形式／用途，现实主义是导演模式。** 不要把它们塞进“题材”一栏互相替代。

## 概念判断与执行

任务契约之后按需判断是否有原创概念空间：作者型可发明画面规则，原著、纪实与广告等约束型从已有事实寻找表达，教学和功能展示可采用极简型；详见[原创概念](creative-concept-engine.md)。原创概念决定作品特色，专业模块决定表现方法，[镜头执行契约](shot-execution-contract.md)检查关键变化是否可按预期被观察，验收模块检查证据。概念不能新增原著事实、产品功效或真实事件。允许有意留白与不揭示。

冲突优先级：用户硬约束与事实边界 → 任务主导意图 → 媒介与形式 → 专业模块 → 创意建议。平台实际限制单独作为执行适配，不未经授权改变创作稿。

## 2. 模块决策权：每个域一个主导，多个模块可以同时在场

模块不是“主类型＋一个副模块”。一个任务可以同时加载叙事、恐怖、动画、声音、空间五个模块；关键是每个**决策域**只有一个主导，其他模块只能约束或建议。

| 决策域 | 谁可主导 | 谁可约束 | 谁只可建议 |
| --- | --- | --- | --- |
| 叙事与人物 | 叙事与表演 | 用户事实、原著、媒介语法 | 动作（给一个动作节拍）、恐怖（给压力） |
| 动作因果 | 动作编排 | 作品物理规则、审查与用户边界 | 恐怖（给威胁）、叙事（给动机） |
| 恐惧与悬念 | 恐怖与悬疑 | 分级、用户边界、事实 | 动作（给威胁）、声音（给静默） |
| 媒介语法 | 动画与故事板 | 用户指定媒介、制作条件 | 运镜（给镜头可能）、叙事（给表演） |
| 空间与摄影 | 空间坐标／导演运镜 | 用户 POV、平台、硬约束 | 动作（要求可读）、恐怖（要求遮挡） |
| 声音 | 声音与节奏 | 用户指定音乐／静音、对白原句 | 动作（要求冲击）、恐怖（要求静默） |
| 风格与资产 | 风格库／资产 | 品牌、参考图职责、用户指定 | 类型模块（给气质） |
| 广告与合规 | 现实主义与广告 | 法规、品牌、平台 | 叙事（给人物）、声音（给记忆点） |
| 节奏与时长 | 通用核心 | 用户时长、平台、事件容量 | 各模块（给本段建议） |

使用规则：

1. **先声明权限，再写正文。** 每个加载的模块写清：它主导哪个域、约束什么、只建议什么。
2. **一个域只能有一个主导。** 两个模块都想主导同一域时，核心按第 6 节优先级裁决，不能“两个都听”。
3. **模块不能自我升格。** 动作模块不能因为出现一把刀就接管整段；动画模块不能把真人物理强加给所有任务；恐怖模块不能把爱情戏改成惊吓戏。
4. **约束高于建议。** 约束是硬边界（如品牌不能出现竞品、用户要静音、原著人物不能死）；建议可以被核心忽略。
5. **可以禁用模块。** 用户明确不要打斗、不要音乐、不要字幕时，相关模块禁用，不是“默认关但可被类型惯例打开”。

## 3. 路由：按维度加载，不按单一主类型

| 任务信号 | 应加载 | 不应默认加载 |
| --- | --- | --- |
| 对话、关系、告别、独白、日常 | 叙事与表演、导演运镜；需要时声音 | 动作、特效、恐怖 |
| 攻防、追逃、枪战、冷兵器、机甲、巨物、军团 | 动作编排、特效与受创、导演运镜、声音；极高速或人海再加高速与多人 | 恐怖、爱情、广告；不要用慢镜代替接触与受力 |
| 恐怖、悬疑、未知威胁、心理压迫 | 恐怖与悬疑、声音与节奏、导演运镜 | 动作；jump scare 不能代替积累 |
| 爱情、暧昧、错过、重逢、亲密 | 叙事与表演、声音与节奏 | 强行误会、狗血台词、过度柔光 |
| 科幻、奇幻、超能力、异世界、神话 | 特效与受创、风格库、能力库；按媒介加动画或真人规则 | 设定倾倒；特效默认拉满；能力无代价 |
| 现实主义、纪录片、社会议题、自然光 | 现实主义与广告、导演运镜、声音 | 英雄光、无因手持、把苦难拍成奇观 |
| 产品、品牌、广告、宣传片 | 现实主义与广告、声音与节奏、导演运镜；需要时 S2 空间 | 功能夸大、产品消失、无关剧情抢戏 |
| 二维、三维、定格、国漫、日漫、动画短片 | 动画与故事板、风格库、声音；按题材再加恐怖／爱情／动作 | 把真人表演与物理直接套给动画 |
| 分镜、故事板、长视频、多段连续、系列 | 动画与故事板、视点与连续、导演运镜 | 平均分镜、固定节拍、每段重开世界 |
| 实验、梦境、超现实、意识流、纯氛围 | 通用核心、叙事与表演、导演运镜、声音；按需 S3 | 强行因果闭环、强行解释、把“看不懂”当深刻 |
| 两种以上题材混合 | 按维度拆开，可同时加载多个模块；每个域一个主导 | 先定一个主类型再只挂一个副模块；所有类型规则全开 |

三个拆解示例：

- **超现实恐怖爱情动画：** 主导意图＝亲密与不安并存；题材＝恐怖＋爱情；媒介＝二维动画；形式＝短片；导演模式＝诗意／实验。主导域：恐怖（恐惧）、叙事（关系）、动画（媒介语法）、声音（声音）、运镜（空间）。动作不加载；轴线可以有意打破，但要有内部逻辑。
- **护肤品广告：** 主导意图＝记住一个产品事实；题材＝生活／美容；媒介＝真人；形式＝15 秒竖屏广告；导演模式＝商业。主导域：现实主义与广告（产品与合规）、声音（产品声）、运镜（产品可读）。动作、恐怖不加载；需要精确质地与瓶身比例时用 S2 世界坐标说明，不套 S1 禁米数。
- **写实枪战：** 主导意图＝相信每一次交火；题材＝动作；媒介＝真人；形式＝短片；导演模式＝写实。主导域：动作（因果与接触）、运镜（空间）、声音（枪声与静默）。恐怖、爱情、广告不加载；特效只服务受创与弹道，不默认拉满。

## 4. 自适应导演决策

先问“这场戏要让观众获得什么体验”，再决定手段。手段之间是平等的，不按“动态高于静态、特效高于克制、快切高于长镜”排序。

| 决策 | 要看什么 | 不要默认 |
| --- | --- | --- |
| 镜头长度 | 观众需要读多少新信息、表演是否连续、动作是否看得清 | 不设统一 4～6 秒；文戏长镜可以 20 秒以上，高速段落可以更短 |
| 机位运动 | 是否跟随人物、揭示空间、制造压迫或保持观察 | 不默认环绕、推拉、甩镜；固定机位也可以是主动选择 |
| 景别 | 观众此刻该读关系、表情、手部、环境还是尺度 | 不默认每句正反打、每段特写 |
| 表演尺度 | 类型、媒介、人物关系、文化语境 | 不默认咬牙、冷笑、流泪；动画表演可更外化，写实可更克制 |
| 特效强度 | 事件后果、类型契约、观众注意力预算 | 不默认核爆、粒子拉满；黑暗里抬头也可以是最强画面 |
| 物理规则 | 作品自己建立的世界规则 | 不默认所有画面都符合现实物理；写实要承重，超现实要自洽 |
| 声音 | 对白、环境、动作、静默、音乐是否有叙事功能 | 未经要求不擅自加音乐、字幕、画面文字与旁白；音乐主导、信息主导任务按目的判断（见[默认矩阵](defaults-and-medium.md)） |
| 节奏 | 场景任务、时长、平台、观众疲劳 | 不默认快切；慢也可以有张力，快也可以有停顿 |

### 总长约束与默认按事件编排

1. **默认按事件推进。** 普通影视创作与模型执行稿以事件及状态变化组织节奏，默认不给单个镜头或镜内阶段标注起止时间码、固定秒数或括号时长。多镜用 `分镜01` / `Shot 01`，真一镜用 `镜内阶段01` / `Phase 01`，静态故事板用 `第01格` / `Panel 01`。编号后直接接画面描述；阶段编号沿同一机位路径连续推进。用户指定正文形式、局部修订或只要某类交付时，沿其范围工作。
2. **总长约束容量。** 用户给定的全片及分段时长写入相应视频复制块，作为容量硬约束；未给总长就按事件推进。机位路径、表演、对白、动作、特效演化与必要结果共同占用观察容量，镜头轻重随观看目标变化。先建立事件链，避免在内部均分秒数、招数或字数后套入画面。
3. **终态倒推后正向核查。** 沿[镜头执行契约](shot-execution-contract.md)从指定终态倒推必要条件、决定性事件和观察机会，再核对串行变化与可并发反馈。返修依次删除重复展示，调整未锁定的机位与焦点使相容反馈同框，再精简技能自行补全的铺垫。保护用户锁定的动作、速度、强度、台词、状态与结局，也保护承担叙事功能的静止、停顿和留白。仍有冲突就在复制块外列出具体瓶颈与可行取舍，等待用户选择。
4. **精确时间按明确要求或任务必需启用。** 用户及母稿已锁定的时点、镜长、小数秒或逐帧设计按原精度保留。已有音轨精确对齐、已确认的 Edit 修改窗口、技术重叠换算或带时间字段的结构化导出，可在完成该任务所必需的位置使用时间表达。必要性须来自实际任务或已确认执行条件；仅给总长、要求快节奏、提到模型名或列出可选能力时，仍采用默认事件序。素材不足以确认精确同步时保留未定项。
5. **局部时间只作用于局部。** 一个时点、局部持续时间或编辑窗口只标在对应事件或技术交付物中。声响通常随动作相位锚定；全片时间轴只在任务确实要求时输出。原著和对白中的“三秒后”等时间属于剧情事实，保留原意。真实视频评审可以记录观察到的实际秒数。
6. **返修尊重已有来源。** 局部返修保留原稿与相邻段落已定时序；明确要求重编为无时间码时，重组事件并重新核对容量。普通跨段先承接位置、持物、伤势、环境和动作后续相位，再推进新事件。工具限制另列适配，具体时间码换算按执行任务使用。

### 空间清晰是默认，但交付方式分三种

- **S1 屏幕模式（默认）：** 表演、普通叙事、动作、广告，用画面左右、前中后景、共同地标、视线与运动方向；复制块不写罗盘方位与抽象米数。
- **S2 世界模式：** 建筑、产品、科学可视化、预演，需要精确尺寸、坐标、楼层与方位时，可以在正文或独立空间说明里写世界坐标；标明“世界空间”，不要套 S1 的禁米数。
- **S3 混合模式：** 复杂动作、巨物、空战、预演，内部建世界图，正文以屏幕投影为主，必要时加一句尺度／方位说明；不要让模型同时收到两套互相冲突的左右。
- 180 度轴线是 S1／S3 保持方向感的工具，不是所有影像的天然法律。实验、梦境、超现实可以有意打破；打破后仍要有一套内部可追踪的逻辑。
- 无意打破、却让观众看不懂谁在哪、往哪走，是空间失败，不是风格。详见[空间描述三模式](spatial-coordinate-system.md)。

### 物理与特效服从作品规则

- 写实战争、现实题材、纪录片：承重、惯性、材料、伤口、光线要可信；不凭空加魔法。
- 科幻／奇幻／武侠／动画：先建立本作品的规则（能力代价、能量来源、世界材质），再让后果自洽；不要求每个画面都符合现实物理，但要求不违反自己刚建立的规则。
- 超现实／梦境／实验：可以违反重力、空间连续、因果；要用重复、声音、色彩、构图让观众感到“这是有意的”。
- 特效强度不默认最大化。克制与爆发都是导演工具；最震撼的画面有时是核爆，有时是人物在黑暗里缓缓抬头。

### 运镜工具平等

固定、手持、轨道、升降、环绕、长焦压缩、广角、主观、伪一镜、真一镜、蒙太奇、甩镜、跳切、定格、慢动作、抽帧，都可以是正确选择。先写清楚“为什么这个镜头要这样看”，再写“怎么运动”。不要为了技术数量堆运镜。

## 5. 模块契约

1. **核心管意图与编排，模块管深度。** 核心决定任务契约、决策权分配、冲突裁决与成功标准；模块只提供该域的专业规则。
2. **按需加载。** 只读当前任务真正需要的模块；不遍历 200 张能力卡、60 张风格卡或全部专题。
3. **模块不能覆盖用户。** 用户明确要静态、长镜、无音乐、无打斗、单语、某一范围时，模块默认值让位。
4. **模块冲突时核心裁决。** 先看用户硬约束，再看任务契约与成功标准，再看媒介语法、类型惯例、模块默认值；把裁决理由放块外。
5. **动作是模块，不是默认。** 只有任务契约判定动作题材、或用户明确要求动作时，才启用动作、高速与战斗视觉精修；特效按奇观、材质、能力或环境变化的实际需求独立启用，非战斗奇幻也可使用。文戏里的一个动作节拍不等于整段动作化。
6. **保留专业深度。** 通用化不是把动作、特效、能力库削平；该调用时仍按原专题的严格标准执行。
7. **不要求单一主类型。** 题材可以多选，模块可以多个同时在场；禁止的是“同一决策域两个主导”，不是“多个模块”。
8. **默认值有矩阵。** 媒介、形式、BGM、字幕、画幅与镜头的起点见[默认矩阵](defaults-and-medium.md)；矩阵不是法律，用户与任务契约优先。

## 6. 通用质量验收

文字交付前，按下面顺序自检；实际生成视频后，再用[通用验收](general-acceptance.md)做同条件核对；跨类型路由是否读对，用[跨类型路由回归](routing-regression.md)的 16 条用例检查。

| 检查 | 通过标准 | 常见失败 |
| --- | --- | --- |
| 契约完整 | 主导意图、题材、媒介、形式、模式、时长、硬约束、成功标准都清楚 | 只写“电影感”；把动画当题材；把广告当故事 |
| 意图匹配 | 交付物就是用户要的类型、媒介、时长与用途 | 用户要文戏，交付打斗；用户要广告，交付世界观短片 |
| 叙事清楚 | 谁、在哪、要什么、遇到什么、结果如何，能按顺序读出来 | 只有氛围，没有事件；靠旁白补因果 |
| 人物与表演 | 行为有目的，情绪有过程，台词有说话者与阶段 | 情绪标签代替表演；每句都吼 |
| 空间可读 | 当前空间模式下的左右、前后景、地标、视线与运动方向能连起来 | 无因越轴、切镜换地图、人物瞬移；S2 与 S1 规则混用 |
| 风格与媒介 | 真人／二维／三维／定格的语言一致；画风服务内容 | 把真人物理套给动画；把动画当低幼 |
| 节奏与时长 | 事件装得下；该长则长，该短则短 | 平均分镜；为凑时长加空镜 |
| 声音 | 对白、环境、动作、静默、音乐各司其职 | 全程 BGM；音效与画面不同步 |
| 提示词可执行 | 可复制、事实一致、无工程说明混入、参考职责清楚 | 块内混入内部世界图、表单标题、分析 |

动作专项的 P0（方向错误、身份串换、参考图插帧、接触缺失等）只在动作任务中作为一票否决；文戏、广告、恐怖、爱情不能用动作 P0 代替通用验收。

## 7. 常见错误

- 把“有张力”自动理解成“打起来”。
- 把“电影感”自动理解成“快切＋环绕＋爆炸”。
- 把 4～6 秒、180 度轴线、真实物理、最大特效当成所有类型的通用法律。
- 把动画、故事板、广告当成题材，和动作、恐怖、爱情并列。
- 只允许“一个主类型＋一个副模块”，导致混合类型被压扁。
- 让两个模块同时主导同一决策域，最后互相抵消。
- 把 S1 的“禁米数”套到建筑、产品、科学可视化的 S2 任务。
- 用户要克制，却加满 BGM、慢镜、粒子与英雄光。
- 用户要实验／梦境，却用普通叙事连续性把它拉回常规。
- 用通用化当借口，删掉动作、特效、能力库的专业标准。

**一句话：先问这次要拍什么，再决定谁来主导哪个域；不要让作品迁就 Skill 的固定模板。**
